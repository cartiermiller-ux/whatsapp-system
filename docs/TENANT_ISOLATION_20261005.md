# 多租户隔离修复（2026-10-05）

## 已实现

- 建立 tenant 表，用户以 tenant_id 外键绑定租户；保留 tenant 名称字段用于兼容现有页面。
- 20 张业务表添加租户归属：号码、账号、资源群、群发、拉群、执行明细、任务日志、消息回执、扫码会话、文案、超链、流水、充值订单、操作日志、代理池、接码订单、采购订单、到账凭据、资源分组、账号检测。用户表另有 tenant_id。
- 数据库会话统一过滤 ORM 查询、聚合、别名查询、批量更新和删除；未绑定租户时不返回业务数据，也不能写入。业务会话禁止原始 SQL/Core 语句及旧 bulk 写入接口。
- 新增记录自动写入当前租户，禁止修改业务资源的租户归属；关联账号、号码、代理、群、文案、分组和任务必须同租户。
- 后台工作器从系统任务确定所属租户，再使用独立租户会话执行、记录日志和扣费。调度器跨租户发现任务不能绕过执行器的隔离。
- 余额统计、充值、消费、退款和调整均作用于当前租户账本。签名到账回调根据系统订单确定归属；消息回执根据账号确定归属。
- 普通业务接口对超级管理员也不开放隐式全库访问；平台租户管理接口独立授权。代理商管理员不能自行确认充值、手工调账或修改全局通道和计费设置。
- 新增租户创建、启用和停用界面；停用撤销该租户所有登录 token。任务执行器在开始及每个目标前检查租户状态；已经发出的外部请求可能完成，不会自动重复发送。
- 删除演示租户选择器，登录返回真实租户归属。更改用户租户撤销其旧 token 并清空当前扫码会话选择。
- 同租户成员可协作使用已登记账号；扫码中的未登记会话仅创建者可访问。跨租户不能读取二维码、停止会话或导出会话文件，也不能共享同一个认证目录。
- 号码、群 JID、资源分组名称的唯一性按租户定义；短链编码和认证目录仍保持全局唯一。

## 迁移策略

迁移入口为 tenancy.migrate_tenants，在启动服务前调用。迁移失败终止启动，不在缺少隔离字段时继续对外服务。

默认租户固定为 ID 1。旧业务数据缺少可信归属时保留在默认租户，不能仅根据操作人猜测号码、账号、群和任务的所有者。明确记录用户 ID 的充值订单、操作日志、扫码会话和检测记录按该用户回填；到账凭据跟随订单。旧账本无法可靠拆分，保留默认租户余额。历史数据若需重新分配，需要单独核对资源和账本，不提供直接修改 tenant_id 的普通接口。

PostgreSQL 使用事务、迁移锁、外键、NOT NULL 和租户索引。SQLite 对旧表补充字段并回填，使用触发器阻止空/无效租户；需要变更旧全局唯一约束的三张资源表在事务内重建。迁移可重复执行。

## 部署流程（已完成）

1. 登录服务器后创建独立 PostgreSQL 演练库，恢复生产备份，在该库导入新版 main 完成迁移，并逐字段比较原有数据。另用空测试库运行 tenant_test 和 operations_test；禁止将测试 URL 指向生产库。
2. 正式切换时停止 API 和健康检查计时器，冻结新写入，保存应用和 PostgreSQL 一致性备份。
3. 上传已验收代码和前端，导入 main 执行迁移；检查所有 21 张归属表不存在空或无效 tenant_id。
4. 启动 API，检查匿名访问 401、管理员正常登录和原有默认租户数据，以及 USE_REAL_SEND 保持 false。
5. 安装健康检查 service/timer，手动验证一次，再启用每分钟检查。仅记录 journal 日志。

旧代码无法直接写入新版 NOT NULL 业务表。回滚必须同时恢复切换前的代码和数据库；生产恢复新写入后不可用旧备份直接覆盖新账本。

## 仍需独立推进

租户隔离不等于计费完整商业化：跨进程扣费预占、失败退款、支付供应商真实链上核验，以及每租户独立供应商凭据仍需单独设计和验收。当前单 API 实例使用进程内通道锁；多实例运行前需迁移到数据库级钱包锁/预占机制。全局服务配置和计费规则只由平台管理员维护。

实现依据：[SQLAlchemy ORM 事件与访问范围过滤](https://docs.sqlalchemy.org/en/20/orm/queryguide/api.html#sqlalchemy.orm.with_loader_criteria)、[ORM UPDATE/DELETE 过滤支持](https://docs.sqlalchemy.org/en/20/orm/queryguide/dml.html#important-notes-and-caveats-for-orm-enabled-update-and-delete)。
